# Source mapping

Reference revision: `19905b75dbea89fbfd424d67fe26c81aaed0e018`. Recipe paths are under `recipe/android/` in `ourapps-ae/OurPoker`.

- `app/src/main/java/app/ourapps/ourpoker/MainActivity.kt` lines 43-88 (the activity, language wrap, sound start-up, permission request, resume and pause hooks, `PokerColors`) -> `implementation/android/src/main/java/ae/androidhost/ShellActivity.kt` and `ShellPalette.kt`: the activity becomes an abstract `ShellActivity` with `permissions`, `language`, `palette`, `Content()` and lifecycle hooks; the hard-coded camera and microphone pair, `Sound.init`, `TableViewModel` calls and the dark scheme colours become overridable members and a `ShellPalette` of numeric colours (with `parseColour` as an addition). Lines 90-137 (`Root`: screens, guides, help bulb, beginner dialog) are poker screens and stay with the recipe.
- `app/src/main/java/app/ourapps/ourpoker/AppLanguage.kt` lines 11-31 -> `implementation/android/src/main/java/ae/androidhost/ShellLanguage.kt` and `LanguageChoice.kt`: the fixed list of four languages, the `ourpoker` preferences name and the call into `ae.i18n.selectLanguage` become constructor arguments and a local `resolveLanguage` (same rule: exact tag, base language, fallback), so the component does not depend on the translations component. `implementation/android/language.ts` repeats the rule for build tools and tests (`generated-platform`).
- `app/build.gradle.kts` lines 1-137 -> `implementation/android/templates/app.build.gradle.kts.template` and `render.ts`: application id, namespace, name placeholder, minimum SDK, compile and target SDK, signing environment variable prefix and component source folders become settings or options; version properties, release signing from environment variables, build features, Java 17 toolchain and the compose bill of materials are kept. Left behind: the `syncArt` task and launcher icon art generation (lines 20-46, 107), `UPDATES_ENABLED` and `SERVER_URL` build config fields (60-62), test options and the connected-test platform task (96-114), the serialization plugin, and the poker, LiveKit, OkHttp and serialization dependencies (126-130), which are options now.
- `build.gradle.kts` lines 1-6 -> `templates/build.gradle.kts.template` (the serialization plugin line dropped); `settings.gradle.kts` lines 1-22 -> `templates/settings.gradle.kts.template` (JitPack repository dropped, project name is an option); `gradle.properties` lines 1-3 -> `templates/gradle.properties.template` unchanged; `gradle/wrapper/gradle-wrapper.properties` lines 1-9 -> `templates/gradle/wrapper/gradle-wrapper.properties.template` unchanged (includes the recipe's Gradle 9.4.0 distribution checksum, not rechecked here).

- `app/src/main/res/drawable/ic_launcher_background.xml` and `ic_launcher_foreground.xml` -> `templates/app/src/main/res/drawable/`: the poker card artwork is kept as a placeholder icon; the adaptive icon file (`templates/ic_launcher.xml.template`) is the one `syncArt` wrote at lines 37-43, now fixed to the two drawables.

- `implementation/android/wrapper/` is the recipe's Gradle wrapper (`gradlew`, `gradlew.bat`, `gradle/wrapper/gradle-wrapper.jar`), unchanged.
